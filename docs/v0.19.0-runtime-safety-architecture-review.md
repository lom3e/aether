# v0.19.0 — Runtime Safety Architecture Review (Final)

## 1. Obiettivo e Filosofia
L'obiettivo della milestone v0.19.0 è consolidare il runtime del framework Aether, trasformandolo in un sistema resiliente di grado enterprise.
La filosofia adottata è strettamente infrastrutturale: il livello di sicurezza non deve mai invadere il dominio cognitivo. Nessun componente di questa milestone emetterà "giudizi" sui ragionamenti dell'agente (es. progress detection) né altererà in modo occulto i prompt per guidare i modelli LLM.

La separazione tra `Agent`, `ExecutionEngine` e `Planner` rimane intoccata. Il runtime applicherà limiti oggettivi, intercetterà eccezioni e troncherà dati immensi, garantendo sempre che l'infrastruttura sopravviva a comportamenti non deterministici o guasti esterni.

---

## 2. Componenti Architetturali Finali

### A. RuntimeSafetyPolicy (Gestione Ciclo di Vita e Scadenze)
- **Responsabilità**: Interrompere forzatamente e oggettivamente l'esecuzione per esaurimento risorse, prevenendo i loop.
- **Competenze Esclusive**:
  - `max_cognitive_cycles` (Limite di giri nel loop dell'agente)
  - `max_replans` (Limite di fallimenti di validazione)
  - `absolute_deadline` (Scadenza cronologica assoluta per il task)
- **Cosa NON fa**: Non analizza i `CognitivePlan`, non deduce se c'è "progresso" e non tenta confronti semantici.
- **Design dell'API**: Interfaccia disaccoppiata e stateless (o minimal stateful) invocata dal runtime. Es. `before_cycle()`, `after_cycle()`, `before_replan()`, `check_deadline()`.

### B. ObservationFactory e ObservationBudget (Sicurezza Memoria)
- **Responsabilità**: Evitare che payload massivi facciano scoppiare la context window dei provider LLM, senza però distruggere l'immutabilità della struttura.
- **Design Architetturale**:
  - Un'astrazione `ObservationBudget` (estendibile in `CharacterBudget`, `TokenBudget`, `ByteBudget`, `ImageBudget`).
  - Una `ObservationFactory` che, ricevendo il risultato grezzo dall'`ExecutionEngine`, applica il budget. Se sforato, i dati vengono troncati e vengono immessi metadata infrastrutturali (es. `truncated: True`, `original_size: X`).
- **Cosa NON fa**: La Factory non crea "System Hints" testuali nel prompt per avvisare il Planner, e non sa nulla dell'LLM. Si limita a marcare oggettivamente il record. Sarà il `Planner` a dover interpretare cognitivamente il campo `truncated=True`.

### C. ResilientProvider (Resilienza Transitoria)
- **Responsabilità**: Garantire che instabilità di rete e rate limiting non facciano collassare l'agente.
- **Design Architetturale (Decorator Pattern)**: `AIProvider` e le sue implementazioni concrete (es. `OllamaProvider`) non sanno nulla di retries. Verrà introdotto un wrapper esterno `ResilientProvider(AIProvider)` che implementa la backoff policy.
- **Policy di Retry**:
  - *Ritenta su*: Errori transitori (HTTP 429, 500, 502, 503, Timeout, Network Error).
  - *NON ritenta su*: Errori deterministici (HTTP 401/403 Invalid API Key, Model Not Found, Bad Schema, Invalid Configuration).

### D. Execution Safety (Gestione Eccezioni)
- **Responsabilità**: Evitare deadlock logici ed execution crash.
- **Design Architetturale (Modello Standard Python)**:
  L'`ExecutionEngine` intercetterà unicamente le eccezioni recuperabili (la classe base `Exception`), tramutandole in una unit observation con `is_error=True`.
  Eccezioni di sistema critiche (`KeyboardInterrupt`, `SystemExit`, `GeneratorExit`, `MemoryError`) verranno lasciate propagare verso l'alto per terminare immediatamente l'OS process (OS-standard compliance).

## 3. Scope della Milestone v0.19.0 (Cosa entra)

1. **`RuntimeSafetyPolicy`** con API hook infrastrutturale (limitatori cicli e deadline assoluta).
2. **`ObservationFactory`** equipaggiata con un `ObservationBudget` scalabile e default non-infiniti ma sicuri.
3. **`ResilientProvider`** tramite wrapper decorator per gestire failure asincrone.
4. Rimodulazione del `try...except` nel **`ExecutionEngine`** per discriminare esattamente `Exception` dalle eccezioni fatali dell'interprete.

## 4. Cosa RIMANE FUORI (Rimandato alle milestone successive)

- **Progress Detection & Cognitive Hash**: Rimosso totalmente. Qualsiasi valutazione per capire se un piano identico sia sinonimo di "stallo" farà parte di un futuro _Cognitive Evaluation Layer_ (v0.20+), dato che un piano identico può essere legittimo se lo stato esterno cambia in background.
- **Execution Budget Cost (Token/Monetario)**: Il budgeting sarà di dimensioni/peso per le Observation, ma non terrà ancora conto della fatturazione dei token (richiede moduli per calcolare token su modelli diversi).
- **Iniezioni nel Prompt**: Qualsiasi modifica per inserire avvisi testuali al LLM sui tronchi di memoria non spetta alla factory.
